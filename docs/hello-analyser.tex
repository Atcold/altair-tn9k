The logic analyser is the tool that shows what travels on a wire. This lesson connects it to the board and checks it on a signal whose meaning is known. The FPGA sends \texttt{Hello world} over a serial line ten times a second, and the message travels on two paths. Through the analyser’s probes, Logic~2 decodes it on the Mac. Through the board’s own USB cable, a terminal prints it. If the two agree, the analyser, its software, and the probing are right.

\section*{What the FPGA sends}

The FPGA sends the 13 characters of \texttt{Hello world\textbackslash r\textbackslash n} one after another on \texttt{tx}. Each character goes out as a UART frame, and each bit of the frame lasts 234 clock cycles. \texttt{busy} is high for the whole message, so the analyser knows when to start. Then the FPGA rests for 100\,ms and starts again. To do this, it keeps track of three things: which character is next, which bit of its frame is on the line, and how long the current bit, or the rest, has lasted.

\subsection*{One character: a frame}

A UART sends one byte as a frame of ten bits, each lasting the same time. The line rests high. A low \emph{start} bit marks the beginning. The eight data bits follow, lowest first, and then a high \emph{stop} bit. After the stop bit, the line can rest, or the next start bit can follow. Nothing marks the bits themselves; the receiver times them from the start bit’s falling edge. This format is called \emph{8N1}: 8 data bits, no parity, and 1 stop bit.

At 115\,200 baud, which here means 115\,200 bits per second, a bit lasts 8.68\,µs. That is 234 cycles of the 27\,MHz clock (27\,000\,000 / 115\,200 = 234.375). The FPGA’s bits are therefore 0.16\,\% short, which is well within what a receiver tolerates.

\subsection*{Reading first}

The design is a \emph{finite state machine}. Before the diagram and the Verilog below, read these sections of Harris and Harris~\cite{ddca}:
\begin{enumerate}
  \item §3.3, \emph{Synchronous logic design}, pp.~117--121. Every change happens at a clock edge, so a state is where the machine waits between edges.
  \item §3.4, \emph{Finite state machines}, pp.~121--139. It gives the design steps, starting from the diagram. Within it, \emph{Moore and Mealy machines}, p.~130, names the kind of machine built here, and \emph{Factoring state machines}, p.~132, splits a machine into a controller and counters, as this design does.
  \item §4.6, \emph{Finite state machines}, in Verilog, pp.~207--211. It shows how a state diagram becomes a \texttt{case} statement.
\end{enumerate}

\subsection*{The state machine}

A state machine has three parts: a register that holds the current state; next state logic, which computes the next state from the current state and the inputs; and output logic, which computes the outputs. At every clock edge, the register takes the next state. When the outputs depend on the current state alone, the machine is a \emph{Moore machine}.

This design is two state machines working together. The \emph{controller} decides what the FPGA is doing: resting, loading a frame, or sending it. The \emph{counters} keep the numbers: how long the rest has lasted, how long the current bit has lasted, how many bits of the frame are left, which character comes next, and, in \texttt{frame}, the bits still to send. The outputs of each machine are inputs of the other. The controller’s state tells the counters what to do at the next clock edge; the counters tell the controller when the rest, a bit, or the frame is over, and when all 13 characters are sent.

What the counters do depends on the controller’s state:
\begin{itemize}
  \item \textbf{In \texttt{REST}}, \texttt{rest\_count} counts the cycles of the rest, and \texttt{char\_index}, which points to the next character, goes back to the first one. When the rest has lasted 100\,ms, \texttt{rest\_done} becomes true and takes the controller to \texttt{LOAD}.
  \item \textbf{In \texttt{LOAD}}, which lasts one cycle, the next character’s frame goes into \texttt{frame}. The frame is a start bit, 8 data bits, and a stop bit. \texttt{bits\_left}, which counts the bits still to send, is set to 10, and \texttt{char\_index} moves on to the next character. When \texttt{all\_sent} is true, no character is left, and the controller goes back to \texttt{REST} instead.
  \item \textbf{In \texttt{SEND}}, \texttt{bit\_count} counts the cycles of the current bit. \texttt{frame} is a shift register, and \texttt{tx} is wired to its lowest bit. Every 234 cycles, \texttt{bit\_done} becomes true. Then the contents of \texttt{frame} move one place to the right, so its next bit reaches \texttt{tx}, and \texttt{bits\_left} goes down by one. After the tenth bit, \texttt{frame\_done} takes the controller back to \texttt{LOAD}.
\end{itemize}

\subsection*{Register-transfer level design}

The design is in \name{rtl/hello/hello.v}. It is described here one block at a time, in the order of the file.

\subsubsection*{Ports and constants}

\inputminted[firstline=6, lastline=16]{verilog}{../rtl/hello/hello.v}

The module has one input, the 27\,MHz clock, and three outputs. \texttt{tx} goes to the board’s USB-serial bridge, and \texttt{tx\_probe} carries the same signal to the analyser’s \name{CH0}. \texttt{busy} goes to \name{CH1}.

\texttt{GAP} is the length of the rest in clock cycles: 2\,700\,000 cycles of 37\,ns make 100\,ms. \texttt{BAUD} is the length of one bit in cycles, and \texttt{N} is the number of characters. A \texttt{parameter} can be changed from outside the module, and the testbench uses this to shorten the rest. A \texttt{localparam} cannot be changed.

\texttt{MSG} holds the whole message as one 104-bit constant, 8 bits per character, with the first character in the top byte. In Verilog, a string in quotes is a sequence of bytes. \texttt{8'h0d} is a \emph{sized literal}. The 8 says that it is eight bits wide, the \texttt{h} says that it is written in hexadecimal, and \texttt{0d} is its value. \texttt{8'h0d} is the carriage return, and \texttt{8'h0a} is the line feed. The braces join the pieces into one vector, with the first piece at the high end. This is called \emph{concatenation}.

\subsubsection*{The state}

\inputminted[firstline=18, lastline=19]{verilog}{../rtl/hello/hello.v}

\texttt{REST}, \texttt{LOAD}, and \texttt{SEND} are names for 0, 1, and 2. Two bits hold three states, so \texttt{state} is a 2-bit register. It starts in \texttt{REST}, the value written after it. \texttt{nextstate} is the value that the next state logic computes. It is declared as \texttt{reg} because an \texttt{always} block assigns it, but it is no register. In Verilog, \texttt{reg} means only that an \texttt{always} block assigns the signal. A clocked block, \texttt{@(posedge sys\_clk)}, makes flip-flops of it, and a block that runs on any change, \texttt{@(*)}, makes gates.

\subsubsection*{The counters and the frame}

\inputminted[firstline=21, lastline=26]{verilog}{../rtl/hello/hello.v}

These are the registers of the counters. Each one is wide enough for its largest value. \texttt{rest\_count} reaches 2\,699\,999, which needs 22 bits, and \texttt{bit\_count} reaches 233. \texttt{bits\_left} counts down from 10, and \texttt{char\_index} counts up to 13, so each needs 4 bits. Every register here starts at the value written after it.

\texttt{frame} holds the ten bits of the frame being sent. \texttt{10'h3ff} is ten bits, all of them 1, so \texttt{tx} is high before the first frame, and the line rests.

\subsubsection*{Counter outputs}

\inputminted[firstline=28, lastline=32]{verilog}{../rtl/hello/hello.v}

Each of these wires compares a counter with its limit. They are combinational logic, and they are the conditions on the controller’s arrows. \texttt{rest\_done} is true on the last cycle of the rest, and \texttt{bit\_done} is true on the last cycle of a bit. \texttt{frame\_done} is true on the last cycle of the last bit of the frame. \texttt{all\_sent} is true once \texttt{char\_index} has gone past the last character.

A line \texttt{wire x = …;} declares a wire and drives it at once. It is the same as \texttt{wire x;} followed by \texttt{assign x = …;}.

\subsubsection*{State register}

\inputminted[firstline=34, lastline=36]{verilog}{../rtl/hello/hello.v}

At every rising edge of \texttt{sys\_clk}, \texttt{state} takes the value of \texttt{nextstate}. The operator \texttt{<=} is the \emph{nonblocking} assignment, which is the one used for registers. With it, every register in the design takes its new value at the same clock edge.

\subsubsection*{Next state logic}

\inputminted[firstline=38, lastline=45]{verilog}{../rtl/hello/hello.v}

This block is the state diagram written as code. Each circle of the diagram is a \texttt{case} branch, and each arrow leaving it is a condition in that branch. In \texttt{REST}, for example, the next state is \texttt{LOAD} when \texttt{rest\_done} is true, and \texttt{REST} otherwise.

The block is combinational. \texttt{@(*)} runs it whenever one of its inputs changes, and it uses \texttt{=}, the \emph{blocking} assignment. The \texttt{default} branch covers the code 3, binary 11, which never occurs.

\subsubsection*{Output logic}

\inputminted[firstline=47, lastline=50]{verilog}{../rtl/hello/hello.v}

\texttt{busy} is high in \texttt{LOAD} and \texttt{SEND}, and low in \texttt{REST}. It depends on the state alone, so the controller is a Moore machine. \texttt{tx} and \texttt{tx\_probe} are both the lowest bit of \texttt{frame}.

\subsubsection*{Counters and frame}

\inputminted[firstline=52, lastline=74]{verilog}{../rtl/hello/hello.v}

This block is one more \texttt{case} on the state. Each branch says what its state does to the counters and to the frame at every clock edge.

\begin{itemize}
  \item \textbf{In \texttt{REST}}, \texttt{rest\_count} counts up, and it goes back to 0 on the last cycle of the rest. \texttt{char\_index} goes back to 0, so the next message starts with the first character.
  \item \textbf{In \texttt{LOAD}}, if a character is left, its frame goes into \texttt{frame}. \texttt{MSG[8*(N-1-char\_index) +: 8]} is a \emph{part select}. It is the 8 bits of \texttt{MSG} that start at bit \texttt{8*(N-1-char\_index)} and go up. When \texttt{char\_index} is 0, they are bits 96 to 103, the top byte, which holds \texttt{H}. The concatenation \texttt{\{1'b1, …, 1'b0\}} puts a stop bit, 1, above the byte, and a start bit, 0, below it. \texttt{1'b1} is one bit, written in binary, with the value 1. \texttt{bits\_left} is set to 10, \texttt{bit\_count} to 0, and \texttt{char\_index} moves on to the next character.
  \item \textbf{In \texttt{SEND}}, \texttt{bit\_count} counts the cycles of the current bit. On the last cycle of the bit, \texttt{bit\_count} goes back to 0, and \texttt{frame} moves one place to the right. \texttt{frame[9:1]} is bits 9 down to 1 of \texttt{frame}, and \texttt{\{1'b1, frame[9:1]\}} puts a 1 above them. The lowest bit drops out, the next bit reaches \texttt{tx}, and a 1, the resting level, comes in at the top. With Verilog’s shift operator, \texttt{>>}, the same is \texttt{(frame >> 1) | 10'h200}. At the same edge, \texttt{bits\_left} goes down by one.
\end{itemize}

The \texttt{default} branch again covers the code that never occurs, and it does nothing.

The pins are in \name{rtl/hello/hello.cst}. \texttt{sys\_clk} is on pin 52, and \texttt{tx}, \texttt{tx\_probe}, and \texttt{busy} are on pins 17, 31, and 32. \texttt{make flash hello} builds the design and writes it to the board’s flash.

\subsection*{In simulation}

Before the board, the design runs in \name{Icarus Verilog}. A testbench, \name{sim/hello\_tb.v}, plays the receiver. At each start bit’s falling edge, it waits half a bit to reach the middle of the bit. Then it samples once per bit and prints the character. It also measures how long \texttt{busy} stays high and low. The rest is shortened to 1000 cycles.

\begin{minted}{bash}
iverilog -g2012 -o build/hello_tb sim/hello_tb.v rtl/hello/hello.v
vvp -n build/hello_tb
\end{minted}

\inputminted{text}{data/hello_tb.txt}

The message decodes. \texttt{busy} is high for 30\,434 cycles. The 13 frames take $13 \times 10 \times 234 = 30\,420$ cycles. Each of the 13 characters adds one cycle in \texttt{LOAD}, and one more cycle in \texttt{LOAD} finds that all are sent.

\section*{The terminal}

The board’s USB-serial bridge, the \name{BL702}, is two USB devices in one, so the Mac shows two serial ports, whose names differ only in the last character. The one ending in 0 is JTAG, which \name{openFPGALoader} uses to load designs into the FPGA; the one ending in 1 is the UART, which \texttt{tx} drives:

\begin{minted}{bash}
ls /dev/cu.usbserial-*
screen /dev/cu.usbserial-XXXX1 115200   # the UART; quit with Ctrl-a k
\end{minted}

\name{screen} ships with macOS. It is a terminal multiplexer, the forerunner of \name{tmux}, and it also opens serial ports: given a port and a baud rate, it shows what arrives. \texttt{Hello world} scrolls by, ten lines a second. \name{picocom} and \name{tio} do the same and nothing else; \name{tio} also reconnects by itself when the board is unplugged and plugged back in.

\section*{The analyser}

The HiLetgo is a clone of the original Saleae Logic: 8 channels, 24 million samples a second.

It needs Logic~2, installed as in the repo’s README. If Logic~2 doesn’t see the analyser while the Mac lists it as a USB device, use PulseView, which is also in the README.

\begin{enumerate}
  \item \textbf{Capture settings.} Click \emph{Device Settings}, then fill in:
  \begin{itemize}[nosep]
    \item \emph{Sample rate}: 4\,MS/s or more, which gives about 35 samples per bit;
    \item \emph{Trigger}, the tab;
    \item \emph{Pattern and Channel}: rising edge on \emph{01. Channel 1}, which is \name{CH1}, the \texttt{busy} line;
    \item \emph{Capture duration after trigger}: 2\,ms, which is longer than the 1.13\,ms of the 13 frames;
    \item \emph{Trim pre-trigger data} and \emph{Glitch filter}: off.
  \end{itemize}
  \item \textbf{Capture.} Click the start button. The capture stops 2\,ms after \texttt{busy} rises. \name{D0}, which is \name{CH0}, shows the 13 frames, and \name{D1}, which is \texttt{busy}, is high for 1.13\,ms around them.
  \item \textbf{Decode.} Add an analyser, \emph{Async Serial}, and fill in its fields in order:
  \begin{itemize}[nosep]
    \item \emph{Input Channel}: \emph{00. Channel 0}, which is \name{CH0}, the \texttt{tx} line;
    \item \emph{Bit Rate (Bits/s)}: 115200;
    \item \emph{Bits per Frame}: 8;
    \item \emph{Stop Bits}: 1;
    \item \emph{Parity Bit}: none;
    \item \emph{Significant Bit}: least significant bit sent first;
    \item \emph{Signal inversion}: non inverted;
    \item \emph{Mode}: normal.
  \end{itemize}
  Then \emph{Save}. Each frame gets a label with its byte, \texttt{0x48} for the first.
  \item \textbf{Read as text.} Right-click a label and choose \emph{Ascii}: the labels read \texttt{H}, \texttt{e}, \texttt{l}, \texttt{l}, \texttt{o}, and so on to \texttt{\textbackslash r} and \texttt{\textbackslash n}.
\end{enumerate}

\textbf{Claude.} Logic~2 has an MCP server (Settings $\to$ Automation $\to$ MCP Server, experimental), which lets Claude start a capture and read the decoded text:

\begin{minted}{bash}
claude mcp add --transport http logic2 http://127.0.0.1:10530
\end{minted}

Saleae lists only its own devices as supported; whether it works with the clone is part of what this lesson finds out.

\section*{Done when}

The decoder reads \texttt{Hello world\textbackslash r\textbackslash n} on \name{CH0}, the terminal prints it, and Claude can start a capture and read the decoded text over the \name{logic2} MCP server.
